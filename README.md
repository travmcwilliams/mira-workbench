# MIRA

**Website:** https://travmcwilliams.github.io/mira-workbench/

**M**ulti-source **I**ngest & **R**ecords **A**nalytics: a local-first data science
workbench with scraping built in.

```
Sources → Scrape/Ingest → records (DuckDB) → Project → Profile → Clean → FE → Model → Export
```

MIRA runs entirely on your machine. A source registry drives polite scrapers that
land data in one canonical DuckDB `records` table. From there a Streamlit app or a
headless CLI takes a dataset through profiling, cleaning, feature engineering,
feature selection and AutoML (scikit-learn always; PyCaret and friends optionally),
with leak-safe temporal splits and an exportable notebook for every run.

## Quick start

Requires Python 3.11 or 3.12.

```bash
git clone https://github.com/travmcwilliams/mira-workbench.git
cd mira-workbench
python -m venv .venv
# Windows: .venv\Scripts\activate    macOS/Linux: source .venv/bin/activate
pip install -e .
playwright install chromium   # optional, only for JavaScript-heavy sites
streamlit run app.py
```

**On Windows**, after cloning just double-click `launch_mira.bat` (or run it from a
Command Prompt in the repo folder). The first run creates `.venv` and installs MIRA
into it, which takes a few minutes; later runs start straight away and reinstall only
when `pyproject.toml` changes after a `git pull`. `launch_mira.bat --setup-only`
installs without starting the app.

The heavy AutoML / profiling stack (PyCaret, XGBoost, LightGBM, CatBoost,
ydata-profiling, SHAP, ...) is an optional extra because its pins conflict with a
plain install:

```bash
pip install -e ".[automl]"
```

Without it, MIRA falls back to its scikit-learn model zoo.

### In the app

1. **Sources & Records**: browse the registry, run a scrape, explore `records`
2. **Home**: create a project from `records`, an upload, or a bundled sample
3. **Pipeline**: configure each stage, use the pre-analysis workbench, run through to a model

## Layout

```
mira/
├── acquire/          # Scraping layer: registry, discovery, ingest agents, macro/events stores
├── core/             # Projects, pipeline engine, schema inference, time joins
├── stages/           # Pipeline stages (profile, clean, feature eng/select, model, ...)
├── pages/ ui/        # Streamlit pages, dashboards, pipeline navigator
├── packs/            # Domain configuration as data (YAML)
├── scripts/          # Batch jobs and studies
├── tests/            # Offline pytest suite
├── mira_cli.py       # Headless CLI
└── app.py            # Streamlit entry point
```

## Canonical `records` table

| Column | Purpose |
|--------|---------|
| `record_id` | Stable id from source |
| `entity_name` | Primary label |
| `location_text` | Geo / jurisdiction |
| `primary_value` | Main numeric measure |
| `period` | Time bucket |
| `source_name` / `source_id` | Lineage |
| `region` | Roll-up geography |

## Headless CLI

```bash
# Scrape a registry source into records
python mira_cli.py acquire --source-id REAL001

# Full pipeline from records through model
python mira_cli.py run --from-records --source-id REAL001 --suggest-target --through model

# Pipeline from a CSV file
python mira_cli.py run --data data/sample/boston_sample.csv --suggest-target --through profile

# Resume / partial run
python mira_cli.py run --project-id abc12345 --from-stage feature_eng --through model
```

## Sample data

`data/sample/` ships small datasets for trying the pipeline:

| File | What it is |
|------|------------|
| `boston_sample.csv` | Classic housing regression sample |
| `restaurant_labor_sample.csv`, `restaurant_daily_sample.csv` | **Synthetic** restaurant labor and daily sales data, regenerated by `scripts/make_synthetic_restaurant_samples.py`. No real business or person is represented. |
| `stock_daily_features.csv`, `news_ticker_study_*.csv` | Small market/news feature panels (derived data) |

Everything else under `data/` is gitignored by default; samples are allow-listed
explicitly in `.gitignore`.

## Configuration

Settings come from environment variables (see `acquire/.env.template`). All are optional:

| Variable | Used for |
|----------|----------|
| `APP_DB_PATH` | DuckDB file for `records` (default under `acquire/db/`) |
| `SERPER_API_KEY` | Optional web-search provider for source discovery |
| `MIRA_USER_AGENT`, `MIRA_CRAWLER_CONTACT` | Identify your crawler to publishers; please set a real contact |
| `MIRA_MARKET_DB` | Optional SQLite daily-bars DB for `scripts/build_stock_panel.py` |

## Pre-analysis workbench and pipeline navigator

Per-column controls before modeling: drop columns, impute (mean/median/mode/constant),
encoding, date parts, log transforms, and feature-selection methods and thresholds.
Settings persist in `project.meta.stage_settings` and are reused by the CLI and the
exported notebooks. Each pipeline stage has its own card (**settings → save → run**)
with artifacts and a last-run summary.

## Responsible scraping

The source registry records each source's `robots.txt` and terms-of-service status,
scrapers rate-limit and back off, and crawlers identify themselves with a configurable
user agent. You are responsible for complying
with each site's terms of service and applicable law when you add or run a source.

## Tests


The suite runs offline. A few integration tests skip automatically when the optional
AutoML stack is not installed.
