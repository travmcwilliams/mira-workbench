Multi-source Ingest & Records Analytics

Data science with scraping built in.

MIRA takes you from a list of web sources to a trained, explained model on your own machine. Scrapers land data in one DuckDB records table, and a twelve-stage pipeline runs from there, in a Streamlit app or a headless CLI.

Get started View on GitHub
Sources→ Scrape / Ingest→ records (DuckDB)→ Profile→ Clean→ Features→ Model→ Explain→ Export

What's in the box

MIRA is one tool for the whole loop: finding data, landing it cleanly, and modeling it honestly. There's no cloud account to set up and no server to run.

Source discovery

Give it a topic and the fields you need. MIRA searches the web, scores candidate pages, probes them for tables and returns a ranked list you can scrape.

Source registry

Sources are data, not code. Each entry records its scraper type, robots.txt and terms status, and lineage, all kept in an embedded DuckDB.

One canonical table

Every scrape normalizes into the same records schema with stable ids and source lineage, so any source can feed any project.

AutoML, your choice of depth

A scikit-learn model zoo works out of the box. Add the optional extra for PyCaret, XGBoost, LightGBM, CatBoost, SHAP and full profiling.

Leak-safe by default

Splits are temporal unless you say otherwise. Feature engineering drops target proxies and reports every column it drops, so no feature disappears silently.

App or CLI, same pipeline

Configure stages in the Streamlit app and replay them from the CLI. Settings persist per project, and every run exports as a notebook.

A twelve-stage pipeline

Each stage has its own settings card. You can save its settings, run it and inspect its output, or resume a run from any stage.

  1. BusinessFrame the goal and target
  2. AcquirePull from records or a file
  3. ProfileTypes, nulls, distributions
  4. EDACorrelations and charts
  5. CleanImpute, dedupe, fix types
  6. Feature engineeringEncodings, date parts, transforms
  7. Feature selectionMethods and thresholds
  8. Data prepTemporal or random split
  9. ModelCompare and tune candidates
  10. EvaluateMetrics and diagnostic plots
  11. ExplainSHAP or permutation importance
  12. DeployPackaged pipeline and inference template

Quick start

Requires Python 3.11 or 3.12. Runs on Windows, macOS and Linux.

Install and launch the app
git clone https://github.com/travmcwilliams/mira-workbench.git
cd mira-workbench
python -m venv .venv
# Windows: .venv\Scripts\activate
source .venv/bin/activate
pip install -e .
streamlit run app.py
Or drive it headless
# Find sources for a topic
python mira_cli.py discover --help

# Scrape a registry source into records
python mira_cli.py acquire --source-id REAL001

# Pipeline from a CSV, straight to a model
python mira_cli.py run \
  --data data/sample/boston_sample.csv \
  --suggest-target --through model

Want the full AutoML stack? Run pip install -e ".[automl]".

The records table

Every source lands in one schema. That's what lets the discovery, scraping and modeling halves work together.

ColumnPurpose
record_idStable id from the source
entity_namePrimary label
location_textGeography or jurisdiction
primary_valueMain numeric measure
periodTime bucket
source_name / source_idLineage back to the registry
regionRoll-up geography

Scrape responsibly. MIRA records each source's robots.txt and terms status, rate-limits requests and identifies itself with a configurable user agent. You're still responsible for following each site's terms and the law where you run it.
